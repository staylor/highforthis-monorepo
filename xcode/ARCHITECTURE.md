# Architecture

```
xcode/
├── HighForThis/            iPhone, iPad and Mac app (one multiplatform target)
│   ├── HighForThisApp.swift         the scene, the podcast player, the URL cache
│   ├── ContentView.swift            the tabs
│   ├── API/                         the Apollo client and the servers
│   ├── Models/                      logic that doesn't draw: shows by day, post content, artwork and image
│   │                                sizes, the video feed, the podcast player
│   ├── Views/                       a folder per section, Shared/, and Navigation.swift
│   ├── AppIcon.icon                 the icon, for Icon Composer
│   └── Localizable.xcstrings        strings, with generated symbols
├── HighForThisTests/       unit tests (Swift Testing)
├── HighForThisUITests/     iPhone UI tests
├── HighForThisAPI/         generated by Apollo iOS: operations, schema types and test mocks
├── graphql/                the app's GraphQL operations
└── scripts/generate-api.sh
```

## Data

The API's types are the app's models. Screens read the generated selection sets directly, and extensions add what the website works out for itself, such as a show's headline: its title, or else its artists. Shared fragments (`ShowList_show`, `Video_video`) let one row serve every query that lists shows or videos.

**Fetching.** Each screen is one query. `QueryView` fetches it when the screen appears and again when the query changes, as a year filter does, and shows progress, the data, or the error with Try Again. Pulling to refresh fetches from the network. A changed query keeps the old results on screen until the new ones arrive, and a failed refresh keeps what's showing.

**The client.** `ApolloClient.highForThis` is the one client, with Apollo's in-memory normalized cache. Objects are cached by `id` (`SchemaConfiguration`), so a show refreshed in one list is up to date everywhere. `data(for:)` turns a response without data into an error, and logs errors that come with data, which is still shown.

**Videos** page through the API ten at a time. `VideoFeed` asks for the next page as the end of the list comes into view, starts over for another year, and drops a page that arrives after the list started over. It takes its loader as a closure, which the tests replace.

**Uploads**, the images in posts and the podcast audio, are in the CMS's Cloud Storage bucket (`UPLOADS_URL`) at `destination/fileName`, as the web app's `uploadUrl` builds them. Artist artwork comes from Apple Music URL templates, at most 1500 pixels wide. Images load with `AsyncImage`, which caches in the shared `URLCache`, enlarged at launch so artwork fits in it.

## Posts

Posts are Lexical editor state. `PostBlock.blocks(in:)` flattens the root's children into headings, paragraphs, quotes, images and videos, and, like the website, skips empty text and nodes it doesn't show. Lexical stores text formats as a bitmask (`LexicalFormat`), which becomes `AttributedString` runs, so any mix of bold, italic, underline, strikethrough and code renders. The title and third-level headings follow the website: heavy capitals, in the accent color.

## Navigation

A `TabView` with a tab per section, which becomes a sidebar on iPad and Mac (`.sidebarAdaptable`). Each tab is a `BrowseStack`, a `NavigationStack` that can open any `Route`: a show, artist, venue, episode or post. Routes carry the title, so it's on screen while the rest loads. Detail screens use inline titles.

## Playback

`PodcastPlayer` is one `AVPlayer` for the app, shared through the environment, so an episode keeps playing after its page closes and its page shows Pause when it's opened again. `AVPlayer.isObservationEnabled`, new in 26, lets SwiftUI observe the player's `timeControlStatus` directly. On iOS:

- The audio session uses `.playback`, `.spokenAudio` and `.longFormAudio`, and the app has the audio background mode.
- An `MPNowPlayingSession` publishes the episode to the Lock Screen and Control Center, and handles their play and pause.
- The session activates off the main thread, which iOS 27 warns about otherwise.

## Conventions

- Swift 6 language mode, with main-actor isolation by default. Pure value types and logic are `nonisolated`, like the code Apollo generates, so they work in extensions of the generated types.
- Observation (`@Observable`) and async/await. `.task(id:)` starts and cancels loads with the view.
- Strings are in `Localizable.xcstrings` with symbolic keys. The catalog generates a symbol for each, so `Text(.recommendedShows)` is checked when it compiles.
- `os.Logger` with a category per area (`API`, `Playback`).
- Rows set accessibility identifiers (`show-<id>`, `artist-<slug>`, `venue-<slug>`, `podcast-<id>`, `post-<slug>`, `video-<id>`) for the UI tests.
- Logic that doesn't draw goes in `Models/`, with tests.
- `swift format` with `.swift-format`.
